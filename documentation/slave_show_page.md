# Slave / Show — Replication detail page

Date: 2026-04-10

## Overview

The **slave/show** page displays the full replication status of a single MySQL or MariaDB replica. It is accessed via:

```
/{lang}/slave/show/{id_mysql_server}/{replication_name}/
```

### Files involved

| File | Role |
|------|------|
| `App/Controller/Slave.php` — `show()` | Main action: fetches SHOW SLAVE STATUS, time-series lag data, cluster topology |
| `App/Controller/Slave.php` — `showGraphDay()` | AJAX endpoint: returns one extra day of graph data |
| `App/Controller/Slave.php` — `generateGraphSlave()` | Builds Chart.js 4.5.1 initialization code for lag graphs |
| `App/view/Slave/show.view.php` | Main view template |
| `App/view/Slave/showGraphDay.view.php` | AJAX view: canvas + inline `<script>` for one day |

## Page layout (top to bottom)

### 1. Replication lag graphs

The most consulted section — placed first.

- Displays the last **5 days** of `Seconds_Behind_Master` / `Seconds_Behind_Source` as line charts (one canvas per day).
- A **"Load previous day"** button (top-right of the header) fetches older days via AJAX.
- A colored **health strip** (4 px bar) at the very top reflects the overall replication state:
  - Green (`ok`): IO + SQL running, lag = 0
  - Green (`behind`): running, lag > 0 but < 60 s
  - Amber (`warning`): running, lag > 60 s
  - Red (`critical`): thread(s) stopped, lag NULL, or error present

**Chart.js stack:**

| Library | File |
|---------|------|
| Chart.js 4.5.1 | `App/Webroot/js/chart-4.5.1.umd.min.js` |
| Moment.js | `App/Webroot/js/moment.js` |
| Date adapter | `App/Webroot/js/chartjs-adapter-moment.min.js` |

Chart.js v4 API is used (`scales.x` / `scales.y`, `plugins.title`, `tension`).

**AJAX "Load previous day" flow:**

1. JS reads `data-oldest` from the button (ISO date of the oldest loaded day).
2. Computes `previousDay = oldest - 1 day`.
3. `$.get(GLIAL_LINK + "slave/showGraphDay/" + serverId + "/" + previousDay + "/ajax:true/")`.
4. Response (canvas + inline `<script>`) is prepended into `#slave-graphs-container`.
5. `data-oldest` is updated to `previousDay`.

The `showGraphDay` controller action:
- Sets `$this->layout_name = false` when `$_GET['ajax'] === "true"`.
- Calls `Extraction::extract()` with `groupbyday = true` for the single requested day.
- The view (`showGraphDay.view.php`) renders the canvas and a self-contained `<script>` that initializes the chart (Chart.js is already loaded on the parent page).

**Data format** (generated by `Extraction::extract` with `$graph = true`):

The `graph` column from the SQL query is a `GROUP_CONCAT` of JS object literals:

```
{x:new Date('2026-04-10 00:01:00'),y:0},{x:new Date('2026-04-10 00:02:00'),y:0},...
```

This is injected directly into `data: [...]` in the Chart.js dataset config.

### 2. Replication status + Actions (side by side)

Two cards in a `col-md-6` / `col-md-6` row.

#### Left: Replication status

Metric tiles displaying key variables extracted from `SHOW SLAVE STATUS` / `SHOW REPLICA STATUS`:

| Tile | MariaDB variable | MySQL 8 variable |
|------|-----------------|------------------|
| IO Thread | `Slave_IO_Running` | `Replica_IO_Running` |
| SQL Thread | `Slave_SQL_Running` | `Replica_SQL_Running` |
| Lag | `Seconds_Behind_Master` | `Seconds_Behind_Source` |
| Source | `Master_Host:Master_Port` | `Source_Host:Source_Port` |
| Binlog read | `Master_Log_File` + `Read_Master_Log_Pos` | `Source_Log_File` + `Read_Source_Log_Pos` |
| Relay exec | `Relay_Master_Log_File` + `Exec_Master_Log_Pos` | `Relay_Source_Log_File` + `Exec_Source_Log_Pos` |
| GTID | `Using_Gtid` | `Auto_Position` |

Each variable is resolved with a `??` fallback chain so both MariaDB and MySQL naming conventions are handled.

**Visual indicators:**

All status dots are rendered via `Display::statusDot(string $state)` (`App/Library/Display.php`), which accepts `'ok'` (green), `'fail'` (red + box-shadow pulse), or `'info'` (blue, no pulse). The pulse uses the `status-dot-pulse` keyframes: `--size` controls both the dot size and shadow spread, `--startColor` is the dot/current shadow color, and `--endColor` is the transparent fade-out color.

**IO / SQL thread dot logic:**

| IO | SQL | Dots | Meaning |
|----|-----|------|---------|
| Yes | Yes | green / green | All OK |
| Yes | No | green / red + pulse | SQL thread down — alert |
| No | Yes | red + pulse / green | IO thread down — alert |
| No | No | blue / blue (no pulse) | Replication intentionally stopped |

When both threads are stopped simultaneously, it is treated as a deliberate maintenance state (blue info dots, no alarm). When only one thread is down, the failing thread pulses red to draw attention.

**Other indicators:**
- **Colored pill badge** for lag (green 0 s / amber < 60 s / red > 60 s or NULL). When both threads are stopped: blue badge (not alarming).
- **Relay gap** — estimates the volume (MB/GB) between the SQL thread position and the IO thread position using the master's `SHOW BINARY LOGS` data from Extraction2. Shows the number of binlog files behind. When exact file lookup fails (old binlogs purged), falls back to an estimate based on file number difference × average binlog size (displayed with `~` and *(estimate)*).
- **Sparkline** (last 1 hour) — a 32px-tall Chart.js line chart inside the relay gap tile, showing `Seconds_Behind_Master` / `Seconds_Behind_Source` over the last hour. Same color as the main graphs (`#16285a` + 30% fill). No axes, no labels.
- **ETA to catch up** — computed client-side from the sparkline data points. The algorithm finds the **peak** of the current lag spike by walking backwards from the most recent point, then calculates the recovery rate from that peak (not from the start of the hour, which may have been 0). This avoids skewing the estimate when the lag started mid-window.

  | Trend | Display | Color |
  |-------|---------|-------|
  | Lag decreasing (catching up) | `~3h25` + `~2026-04-10 19:45` | green |
  | Lag increasing | `increasing` | red |
  | Lag stable (no change) | `stable` | amber |
  | Lag = 0 | `caught up` | green |

  **ETA algorithm detail:**
  1. Start from the last data point (current lag).
  2. Walk backwards to find the peak — the highest `y` value before the current descent.
  3. `rate = (peak.y - current.y) / elapsed_seconds_since_peak` — seconds of lag recovered per real second.
  4. `eta = current.y / rate` — seconds until lag reaches 0.
  5. Display both relative duration (`~3h25`) and absolute date/time (`~2026-04-10 19:45`).

- **SSL tile** with green dot (Yes + cipher), red dot with box-shadow pulse (No), or amber text (Ignored). SSL detection is compatible with MySQL 8.4+ (`Source_SSL_Allowed`, `Source_SSL_Cipher`) and older versions (`Master_SSL_Allowed`, `Master_SSL_Cipher`).
- **Red error banner** at the bottom if `Last_SQL_Error`, `Last_IO_Error`, or `Last_Error` is non-empty. Multiple errors are shown separately with **IO:** / **SQL:** prefixes.

#### Right: Actions

Grouped by function:

| Group | Buttons | SQL executed |
|-------|---------|-------------|
| **Topology** | Master → Slave selectors + Switch | Switch master (selects pre-filled with current master/slave) |
| **Replication** | START / STOP / SKIP | `START SLAVE`, `STOP SLAVE`, `SET GLOBAL sql_slave_skip_counter = 1` |
| **GTID** | Activate / Deactivate | See GTID section below |
| **Rebuild** | Reload from Master | Triggers `reload` action (only shown if `$data['db_on_master']` is set) |
| **Parallel threads** | Slider + input + Apply | `STOP SLAVE` → `SET GLOBAL slave_parallel_threads/workers = N` → `START SLAVE`. Max = min(50, CPU×2) |

Dangerous actions (SKIP, Rebuild) have a `confirm()` dialog. Parallel threads Apply also confirms (stops/restarts replication).

## GTID detection and button logic

GTID state is detected differently on MariaDB and MySQL. The view handles both engines with a single code path.

### Detection

```php
$using_gtid_raw = $sv['Using_Gtid']  ?? null;   // MariaDB
$auto_position  = $sv['Auto_Position'] ?? null;  // MySQL

if ($using_gtid_raw !== null) {
    // MariaDB
    $gtid_active  = ($using_gtid_raw !== 'No' && $using_gtid_raw !== '');
    $gtid_display = $using_gtid_raw;  // "Slave_Pos", "Current_Pos", or "No"
} elseif ($auto_position !== null) {
    // MySQL
    $gtid_active  = ($auto_position === '1' || $auto_position === 1);
    $gtid_display = $gtid_active ? 'Enabled (Auto Position)' : 'Disabled';
} else {
    // No GTID support (MySQL < 5.6)
    $gtid_active  = false;
    $gtid_display = '';
}
```

### Button state matrix

| Engine | Variable | Value | `$gtid_active` | Grayed button |
|--------|----------|-------|----------------|---------------|
| MariaDB | `Using_Gtid` | `Slave_Pos` / `Current_Pos` | `true` | Activate |
| MariaDB | `Using_Gtid` | `No` | `false` | Deactivate |
| MySQL 5.7+ | `Auto_Position` | `1` | `true` | Activate |
| MySQL 5.7+ | `Auto_Position` | `0` | `false` | Deactivate |
| MySQL < 5.6 | _(absent)_ | — | `false` | Deactivate |

When `$gtid_active` is `true`:
- "Activate" is rendered as `<a class="btn disabled" disabled>` (no href, grayed out).
- "Deactivate" is a normal clickable link.

When `$gtid_active` is `false`:
- "Activate" is a normal clickable link.
- "Deactivate" is rendered as `<a class="btn disabled" disabled>`.

### SQL executed by the controller

**`activateGtid()`** (currently MariaDB-only syntax):
```sql
STOP SLAVE '{connection_name}';
CHANGE MASTER '{connection_name}' TO MASTER_USE_GTID = slave_pos;
START SLAVE '{connection_name}';
```

**`deactivateGtid()`** (currently MariaDB-only syntax):
```sql
STOP SLAVE '{connection_name}';
CHANGE MASTER '{connection_name}' TO MASTER_USE_GTID = no;
START SLAVE '{connection_name}';
```

> **Note:** These SQL statements use MariaDB syntax. For MySQL, the equivalent would be:
> - Activate: `CHANGE MASTER TO MASTER_AUTO_POSITION = 1;`
> - Deactivate: `CHANGE MASTER TO MASTER_AUTO_POSITION = 0;`
>
> A future improvement should detect the engine and use the appropriate syntax.

### 3. SHOW SLAVE STATUS (collapsible, collapsed by default)

The full output of `SHOW SLAVE STATUS` displayed in a two-column table. Collapsed by default to avoid visual clutter — the important variables are already shown in the status card above.

- Click the header to expand/collapse (Bootstrap `data-toggle="collapse"`).
- A badge shows the total number of variables.
- The table is split at the midpoint into two `col-md-6` columns.

### 4. Switch Master To (collapsible, collapsed by default)

Allows changing the replication source. Collapsed by default and marked as _(advanced)_ because it is a rare and potentially dangerous operation.

Contains two server selectors (loaded via `Common::getSelectServerAvailable`) and a "Switch" button.
